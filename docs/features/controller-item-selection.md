# Presentation Controller item selection

Confirmed intent: user request, October 26, 2026.

## Purpose and operator workflow
Selecting an outline item activates its current cached document in Redux. The existing slide editor and slide grid render at `/controller` or `/aux-controller/:profileId`, keeping their instances across item switches.

## Product decisions
- Individual item URLs are no longer supported. Legacy item URLs redirect to their own workspace root without decoding or reconstructing selection.
- Cached mouse/touch, arrow-key and continuous-scroll selection is synchronous, performs no document reads, and never turns item loading on. Actual library/settings sections retain navigation.
- `_id` identifies the document; `listId` identifies its outline occurrence. Reselecting and switching occurrences preserve unsaved document content and unresolved conflicts.
- Shift, Ctrl/Cmd, long press and selection-only actions do not activate an item. Library Add and read-only View details retain their established behavior. Explicit item creation/open actions select the actual occurrence in Redux.
- Initial entry restores only an established occurrence after outline/cache initialization. Missing or temporarily unavailable selection does not choose a replacement. Church resets and auxiliary controller scopes retain isolation.
- The Current Service Workspace Displays preview follows the church-wide active Presentation outline. If that outline is missing or invalid, it falls back to the persisted Presentation selection and then another Presentation outline. Aux previews follow their own persisted selection and never borrow a Presentation outline. The read-only preview refreshes after initial remote replication completes.
- Standard mutation-owner middleware, autosave revisions/conflicts and undo policy remain authoritative. Cached selection never replaces the cache with outline snapshots.
- Cross-device outline sync merges independent row edits and independent row moves against the last synchronized baseline. Drag destinations retain stable neighboring-row anchors and the selected outline owner while they are pending. If both devices change the same row field, delete and edit the same row, move one row to incompatible destinations, or provide an ambiguous legacy reorder without usable move history, the local draft is retained for a focused review. The review opens on request from a compact sidebar notice.
- Outline-content reads use the PouchDB winner. Historical losing leaves do not trigger review, mark content dirty, block operation, or authorize merges/deletions. Diagnostic inspection and graph-validated maintenance are separate explicit operations.
- ItemLists registry reads and writes use CouchDB's winning revision. Historical losing registry branches do not block normal operation, are not merged into the winner, and remain intact unless an explicitly authorized operation handles them. Registry writes still read the latest winner, merge unrelated field changes, retry revision races, and retain current-session edits that overlap another saved change.
- Outline loading commits content only after a stable read. Repeatedly invalidated initial reads stop after a bounded retry and show an error instead of initializing an empty outline; background reads preserve usable content. Harmless registry changes do not reload overlays or overlay history.
- Ordinary outline saves read the current winner, reconcile the operator draft against its own baseline, and use bounded CAS retries. They extend only that winning branch while preserving historical leaves; history and losing branch bodies are not read.
- Genuine unresolved drafts retain their original comparison baseline and latest saved items for focused current-edit review. Navigation and undo bookkeeping preserve them. Choosing specific edits retains the visible draft until successful acknowledgment; failed choices can be retried. Drafts live in memory for the application session and are cleared on sign-out/reload.
- Try again explicitly retries the latest selected outline through its existing load effect. It preserves usable content, bounds invalidated reads, ignores obsolete database/profile/selection results and does not reinitialize libraries or overlays during background retries.
- Opening and replication hydrate usable winning content without revision maintenance, including view-only Controllers. Content activation retires loaded identity and baseline with the list. Temporary loading emptiness cannot become authored delete-all; explicitly removing all initialized rows still saves normally.
- Registry save errors apply only to current unsaved edits. Retry re-reads the winning revision; safe unrelated edits continue to save while a conflicting field remains parked. The operator can explicitly keep current edits over overlapping saved values. Historical branch comparisons and retirement are not part of the controller workflow.
- Pending registry edits remain visible when the controller is reopened. They are rebased onto the saved winner for display while the database baseline stays unchanged; eligible queued work resumes saving, and failed edits remain available for Retry save or Keep my changes.
- Registry teardown drains the queue against the captured owner and database before that database is destroyed. A failed or conflicting intent stays attached to that logical church/controller owner and is restored for Retry save or Keep my changes when the same owner opens a new database handle; it cannot publish into a different church.
- The outline an operator is viewing is local to that device's controller runtime and remains isolated by controller scope. Selection-only changes do not write the shared registry or propagate to other devices. On controller initialization, presentation scope starts at the church-wide active outline and an auxiliary scope starts at its first outline. The church-wide active outline remains shared and is changed only by the existing explicit live-outline action.
- The Current Service Workspace can open without visiting a controller first. While Redux has no initialized registry, its read-only outline preview loads the winning ItemLists document and refreshes it on registry notifications, using the live outline for presentation scope or the first outline for an auxiliary scope. A registry refresh reloads outline content only when the effective selection changes; harmless registry changes preserve the preview without a skeleton. This fallback synchronization is confirmed by the October 28, 2026 preview regression request.
- Media preparation follows the active Redux document, including local video input, without changing display transmission or introducing media caches.
- Thumbnail rendering and virtualization are outside this change.

Approval sources for these decisions: the October 26, 2026 request to remove item routing and make presentation selection instant; the October 27, 2026 request to fix cross-device outline synchronization risks; and the October 28, 2026 requests to use the winning ItemLists revision without operator-facing historical branch review, keep outline selection local, restore pending registry edits after navigation, and load standalone Current Service previews before the controller initializes. Draft retention and actionable retry/keep-current actions for genuine current-session registry edits are additionally authorized by the October 28, 2026 request. The November 11, 2026 outline revision conflict strategy request supersedes historical outline-content review during normal operation, while preserving protection for active overlapping edits.
