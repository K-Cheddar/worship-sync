# Adversarial review process validation

Use these six known counterexamples to validate that the review method prompts useful investigation. They are process acceptance scenarios, not claims that the current branch still contains these defects and not a promise that the method finds every bug.

| Counterexample | Rule that prompts investigation and adversarial sequence | Implementation evidence to inspect | Regression evidence | Why the old process could miss it |
| --- | --- | --- | --- | --- |
| Overlapping Media saves lose an edit while advancing the baseline | Pass A identifies the invariant “a newer edit is never lost or acknowledged as saved prematurely.” Pass B traces B starting, C being edited, and B/C settling in an adversarial order. Use the Media matrix. | Media writer/queue, Redux edit source, persisted document reads/writes, response guards, and the exact baseline/acknowledgment update. | Gate writes/promises deterministically; resolve an older write while a newer edit is pending; assert both final Redux state and PouchDB plus the saved indicator. | General concurrency guidance could still be applied only to tested happy paths; without deriving the out-of-order sequence independently, a single-save test may appear adequate. |
| PouchDB-only Media moves to the wrong folder on Keep Contents | Pass A names semantic location as an invariant. Sequence: Redux omits an item that exists in PouchDB -> Keep Contents deletes its folder -> inspect where the item is rehomed. Use the Media matrix. | The deletion entry point and helper, which snapshot is authoritative, Pouch reads, folder-parent resolution, and item/folder persistence. | Seed the item only in PouchDB, perform Keep Contents, and assert the actual surviving ancestor and final persisted reference. | Structural validity checks may accept a root `folderId`; tests whose Redux fixture mirrors PouchDB cannot expose the divergent snapshot or wrong logical parent. |
| Two approved CSV aliases collide when creating the same destination position | Pass A distinguishes entity identity from source-row/alias identity. Sequence: approve two source aliases for one new team/position -> commit both mappings. Use the CSV matrix. | Preview normalization, approved resolution payload, destination identity/reconciliation map, creation deduplication, and row assignment application. | Commit multiple rows/aliases and assert one intended destination position ID exists and every approved row refers to it. | Preview and commit may each look correct for one alias; helper-level tests or a test with only one row do not prove multi-alias identity consistency. |
| Unrelated CSV option change makes a created dependency unrecognizable | Pass A asks which key fields define the dependency entity. Sequence: create a team/position, fail a later step, change merge/replace or blank-clearing, retry/re-review. Use the CSV matrix. | Durable dependency key construction and lookup, partial results, option hashing, and re-preview/commit reconciliation. | Fail after dependency creation, change only an unrelated option, retry, and assert the same dependency ID is recognized with no duplicate while the changed option applies to its own behavior. | A same-options retry test misses a key that accidentally includes the full settings object; retry guidance alone does not specify key identity. |
| SMS challenge renewal fails after refresh because phone is unavailable | Pass A treats refresh as a lifecycle boundary. Sequence: create challenge -> refresh -> restore challenge -> request a replacement code. Use the invitation/SMS matrix. | Challenge persistence/restore payload, phone input state and visibility, renewal request requirements, server binding to consent/phone, and stale token handling. | Remount from persisted recovery state and invoke renewal; assert it has the required confirmed phone or asks for it, and does not message an unintended number. | An expiry test in the original mounted component retains the phone in React state and never exercises the actual recovery state. |
| A concurrent move of a deleted Media folder rehomes children under the wrong ancestor | Pass A identifies intended logical ancestry and write-time authority. Sequence: deletion begins for folder F -> F or its parent moves -> deletion resumes -> inspect each child's destination. Use the Media matrix. | Folder move/delete serialization or revision conflict handling, fresh parent lookup, subtree traversal, and the Keep Contents rehome calculation. | Hold deletion across a controlled folder move; assert the final folder tree and child parent match the intended post-move semantics in persisted state. | Code review can confirm every ID is valid and deletion's local tests pass while never interleaving the valid move with the delete. |

Each example demonstrates why the workflow should be stated, the scenario independently derived, the enforcement path traced, and the test ordering inspected before reporting `Pass`. A missing test is a coverage gap; it is not by itself proof of a production defect.
